# 系统：游戏状态流转与页面流程 V1

文件名：`系统_游戏状态流转与页面流程.md`  
项目阶段：V1 核心玩法原型  
目标平台：手机竖屏  
推荐开发环境：Godot  
文档状态：页面参考图对齐版（已补充通用 3 选 1节点与背包视图）  

---

## 0. 核心结论

V1 的页面结构不采用“一个节点一个页面”的方式，而采用：

```text
少量独立页面
+
局内主页面 RunBoardPage
+
RunBoardPage 内部模式 / 面板 / 弹窗 / 覆盖层
```

关键原则：

```text
游戏状态可以细
页面数量要少
节点状态不等于独立页面
RunBoardPage 承载大部分局内流程
后续新增页面不能破坏主流程
```

## 1. 手机竖屏分辨率定稿

### 1.1 推荐设计分辨率

V1 推荐主设计分辨率：

```text
1080 × 2340
```

比例：

```text
9 : 19.5
```

选择理由：

| 项目 | 结论 |
|---|---|
| 适配方向 | 手机竖屏 |
| 参考图比例 | 接近 9:19.5 |
| UI 信息量 | 能容纳上半区事件 / 商店 / 战斗，下半区回路 / 背包 / 玩家信息 |
| 现代手机适配 | 比 1080×1920 更适合全面屏长屏 |
| Godot 开发 | 作为逻辑设计尺寸，实际设备以 expand 策略扩展可见高度 |

### 1.2 安全布局区

建议把界面拆成三层高度：

```text
主设计画布：1080 × 2340
兼容扩展：上下 expand
基础安全区：顶部 120px，底部 90px 起步
核心安全区：1080 × 2130，范围为 y=120～2250
```

推荐 UI 区域：

```text
0    ┌────────────────────┐
     │ 顶部设备预留区      │ 120，不放关键按钮
120  ├────────────────────┤
     │ 顶部状态栏 / 菜单区 │ 可放标题、资源、返回入口
180  ├────────────────────┤
     │                    │
     │ 上半区：当前事件区  │ 分支 / 商店 / 战斗 / 奖励
     │                    │
1180 ├────────────────────┤
     │ 中下区：战斗回路区  │ 2×5 槽位，常驻或半常驻
1700 ├────────────────────┤
     │ 底部：玩家信息区    │ 角色、耐久、金币、入口按钮
2250 ├────────────────────┤
     │ 底部设备预留区      │ 90 起步，不放确认按钮
2340 └────────────────────┘
```

### 1.3 Godot 适配建议

建议项目基础设置：

```text
Viewport Width  = 1080
Viewport Height = 2340
Stretch Mode    = canvas_items
Stretch Aspect  = expand
Orientation     = Portrait
```

适配原则：

| 场景 | 处理 |
|---|---|
| 更高屏幕 | 上下区域可以拉伸，核心按钮仍在安全区内 |
| 更矮屏幕 | 压缩上半区背景高度，不压缩核心按钮和卡牌 |
| 刘海屏 / 挖孔屏 | 顶部状态栏下移，菜单按钮放安全区内 |
| 圆角屏 | 四角不要放关键按钮 |
| 平板竖屏 | 保持主内容居中，左右增加背景延展 |

UI 安全区规则：

```text
顶部安全边距：至少 120px。
底部安全边距：至少 90px，并允许随系统导航条继续增加。
关键确认、返回、购买、开战、结算按钮必须落在 y=120～2250 内。
上下 expand 增加的空间只承载背景、过渡留白或可滚动区域，不承载必须点击的固定按钮。
```

### 1.4 不建议的基准分辨率

| 分辨率 | 不推荐原因 |
|---|---|
| 720×1280 | 原型可用，但设计精度不足 |
| 1080×1920 | 16:9 偏短，不适合参考图这种长竖屏布局 |
| 1440×3200 | 设计成本高，开发与切图压力更大 |

V1 定稿：

```text
主设计尺寸使用 1080×2340。
兼容扩展使用上下 expand。
所有关键 UI 放入顶部 120px、底部 90px 起步的安全区内。
```

## 2. 页面结构总览

### 2.1 页面分层

V1 页面分为四类：

| 层级 | 名称 | 作用 |
|---|---|---|
| Page | 独立页面 | 完整切换场景或大页面 |
| RunBoardMode | 局内主页面模式 | RunBoardPage 内部的当前状态表现 |
| Panel | 局部面板 | 商店、分支、奖励、战斗选择等局部内容 |
| Overlay / Popup | 覆盖层 / 弹窗 | 卡牌详情、背包、合成、结算、确认提示 |

### 2.2 最终页面策略

```text
状态机保持完整
页面数量保持克制
局内内容集中在 RunBoardPage
后续页面用 PageRegistry 扩展，不写死数量
```

## 3. V1 独立页面清单

### 3.1 必做独立页面

| 页面 | 类型 | V1 是否必须 | 说明 |
|---|---|---:|---|
| MainMenuPage | 独立页面 | 是 | 主菜单、进入游戏 |
| CharacterSelectPage | 独立页面 | 是 | 角色选择，V1 可只有 1 个角色 |
| StartCampPage | 独立页面 | 是 | 初始营地，3 选 1 初始秘宝少女 |
| RunBoardPage | 独立页面 | 是 | 局内主页面，承载绝大多数流程 |
| RunVictoryPage | 独立页面 | 是 | 整局胜利结算 |
| RunDefeatPage | 独立页面 | 是 | 整局失败结算 |

### 3.2 暂不确定但建议预留的独立页面

这些页面 V1 不一定全部实现，但接口要预留，不限制后续扩展：

| 页面 | V1 建议 | 说明 |
|---|---|---|
| SettingsPage | 可后置 | 音量、画质、语言、震动 |
| ArchivePage / CollectionPage | 可后置 | 图鉴、秘宝少女收集展示 |
| AchievementPage | 可后置 | 成就，V1 可不做 |
| RunHistoryPage | 可后置 | 历史战绩，V1 可不做 |
| HelpPage / RulePage | 建议预留 | 规则说明、术语说明 |
| DebugPage | 开发期需要 | 调参、跳状态、给金币、生成战斗 |
| PauseMenuPage | 可做成 Overlay | 局内暂停菜单，也可以不是独立页 |

定稿原则：

```text
V1 文档只锁定主页面，不锁死后续页面。
新增页面只能通过 PageRegistry 注册，不直接改主状态机结构。
```

### 3.3 V1 必做局内功能视图

这些视图不强制做成独立路由页面，但必须在 V1 中能被打开、关闭和复用。

| 视图 | V1 形态 | 说明 |
|---|---|---|
| BagPage / BagOverlay | RunBoardPage 内全屏或半屏覆盖层 | 背包查看、上阵、出售、卡牌详情入口 |
| CardDetailOverlay | 覆盖层 | 查看秘宝少女完整信息 |
| GenericNodeChoicePanel | RunBoardPage 内通用 3 选 1 面板 | 补给节点、金币节点、事件节点先共用 |
| RewardSelectOverlay | 覆盖层 | 战斗后奖励、升级奖励、技能 3 选 1 |

背包在文档中需要显式列为一个局内功能视图。V1 可以先做成 `BagOverlay`，如果后续需要完整切页，可升级为 `BagPage`，不影响状态机。

## 4. RunBoardPage 定义

RunBoardPage 是 V1 最核心页面。

它不是单一功能页面，而是局内所有主要内容的容器。

```text
RunBoardPage
├─ 顶部状态栏
├─ 上半区当前内容区
├─ 中部战斗 / 事件表现区
├─ 下半区战斗回路区
├─ 底部玩家信息区
└─ 弹窗 / 覆盖层系统
```

### 4.1 RunBoardPage 常驻内容

| 区域 | 内容 |
|---|---|
| 顶部状态栏 | 金币、阶段、普通战胜利数、菜单按钮 |
| 当前内容区 | 分支、商店、补给、战斗、奖励等 |
| 战斗回路区 | 最大 2×5 槽位、锁定槽、已上阵秘宝少女 |
| 玩家信息区 | 当前角色、局内耐久、经验 / 等级、背包入口、奖励入口 |
| 覆盖层 | 卡牌详情、背包、合成结果、胜负结算、确认提示 |

### 4.2 RunBoardPage 内部模式

```gdscript
enum RunBoardMode {
    NONE,

    BRANCH_SELECT,
    SHOP,

    # 补给节点、金币节点、普通事件奖励等统一使用 3 选 1 通用节点面板
    GENERIC_NODE_CHOICE,

    SYNTHESIS_ANIMATION,
    FORMATION_EDIT,

    COMBAT_BRANCH_SELECT,
    COMBAT,
    COMBAT_RESULT,

    REWARD_SELECT,
    BOSS_INTRO
}
```

### 4.3 RunBoardPage 内部面板

| 面板 | 作用 | 是否独立页面 |
|---|---|---:|
| BranchSelectPanel | 每轮分支 2～3 选 1 | 否 |
| ShopPanel | 商店购买、刷新、锁定、出售 | 否 |
| GenericNodeChoicePanel | 补给 / 金币 / 事件节点的 2～3 选 1 通用选择面板 | 否 |
| NodeRewardFeedback | 选择后的奖励反馈、飞字、数值跳变 | 否 |
| FormationPanel | 回路编辑、拖拽摆放 | 否 |
| CombatBranchPanel | 战斗分支选择 | 否 |
| CombatPanel | 自动战斗展示 | 否 |
| RewardSelectPanel | 战斗后奖励 3 选 1 | 否 |

### 4.4 RunBoardPage 覆盖层

| 覆盖层 | 作用 |
|---|---|
| CardDetailOverlay | 查看卡牌详情 |
| BagOverlay | 背包 / 库存查看 |
| SynthesisResultPopup | 合成升格反馈 |
| CombatResultOverlay | 战斗胜利 / 失败展示 |
| RewardPopup | 单个奖励或多奖励展示 |
| ConfirmPopup | 退出、出售、跳过确认 |
| BossUnlockedPopup | Boss 解锁提示 |
| PauseOverlay | 局内菜单 / 暂停 |
| RuleTipOverlay | 规则说明 |

## 5. 不作为独立页面的节点

以下内容是状态、模式、面板或弹窗，不是独立页面。

| 原节点 / 功能 | 正确定义 | 表现形式 |
|---|---|---|
| SupplyNode | 局内补给节点 | RunBoardPage 内 GenericNodeChoicePanel，2～3 选 1 |
| GoldNode | 金币 / 资源节点 | RunBoardPage 内 GenericNodeChoicePanel，2～3 选 1 |
| SynthesisCheck | 自动合成检查 | 逻辑状态 + 合成动画弹窗 |
| FormationEdit | 构筑编辑状态 | RunBoardPage 下半区编辑模式 |
| CombatResult | 战斗结算状态 | RunBoardPage 覆盖层，不单开页面 |
| RewardSelect | 奖励选择 | RunBoardPage 内覆盖层 |
| CardDetail | 查看卡牌 | Overlay，不切页面 |
| Bag | 背包 | Overlay 或抽屉层，不切页面 |

定稿句：

```text
SupplyNode、GoldNode、SynthesisCheck、FormationEdit、CombatResult 都不是独立 Page。
其中 SupplyNode 与 GoldNode 在 V1 先共用 GenericNodeChoicePanel，按类似 3 选 1 的通用结构实现。
```

## 7. 主流程

### 7.1 开局流程

```text
MainMenuPage
↓
StartNewRun
↓
CharacterSelectPage
↓
RunInit
↓
StartCampPage
↓
StarterTreasureSelect
↓
RunBoardPage / BranchSelect
```

### 7.2 普通轮次流程

```text
RunBoardPage / BranchSelect
↓
BranchResolve
↓
ShopNode / SupplyNode / GoldNode
↓
SynthesisCheck
↓
FormationEdit
↓
CombatBranchSelect
↓
Combat
↓
CombatResult
↓
BranchSelect / BossIntro / RunDefeat
```

### 7.3 Boss 流程

```text
normal_win_count >= normal_win_target
↓
BossIntro，可选
↓
BossCombat
↓
CombatResult
├─ Boss 胜利 → RunVictoryPage
└─ Boss 失败 → RunDefeatPage
```

## 10. 各页面定义

## 10.1 MainMenuPage

### 作用

局外入口页面。

### UI 实现约束

MainMenuPage 属于核心 UI 页面，必须遵守 `规范_Codex_Godot_UI组件化与RenderedState实现协议.md`。

```text
以 UI 协议为准。
不得把 MainMenuPage 参考图或生成整图作为运行时整页 UI。
不得使用 HBoxContainer / VBoxContainer / GridContainer 自动排版主菜单核心控件。
必须拆分背景、头像框、入口按钮、主按钮、标题 / 文本等独立组件。
必须通过 data/ui/rendered_states/main_menu.rendered_state.json 显式描述 rect、z_index、visible、variant、binding 和 interaction。
页面脚本只读取 Rendered State 并绑定事件，不得根据屏幕尺寸或按钮数量重新推导核心布局。
```

### 主要内容

```text
游戏标题
主视觉角色 / 队伍
进入游戏按钮
设置入口
图鉴入口，可后置
成就入口，可后置
退出按钮，可后置
```

### 主要事件

| 事件 | 结果 |
|---|---|
| 点击进入游戏 | START_NEW_RUN |
| 点击设置 | 打开 SettingsPage 或 SettingsOverlay |
| 点击图鉴 | 打开 CollectionPage，V1 可后置 |

## 10.2 CharacterSelectPage

### 作用

选择本局角色。V1 可以只有 1 个可选角色，但必须保留扩展结构。

### 页面结构

```text
顶部：角色名称 / 稀有度 / 进度信息
中部：角色大立绘
底部：角色列表横向滚动
底部主按钮：开始冒险
```

### V1 规则

```text
只有 1 个角色可选
角色能力字段预留但不启用
锁定角色可显示但不可选
```

### 主要事件

| 事件 | 结果 |
|---|---|
| 选择角色 | 更新 selected_character_id |
| 点击开始冒险 | RUN_INIT |
| 查看角色能力 | 打开角色详情弹窗，V1 可简化 |

---

## 10.3 StartCampPage

### 作用

开局营地，给玩家第一个构筑方向。

### 页面结构

```text
顶部：角色 / 局内信息
中部：营地背景 / 初始 NPC
底部：3 个初始秘宝少女选项
主按钮：确认选择 / 开始冒险
```

### V1 内容

```text
发放初始金币
展示 3 个初始秘宝少女
玩家选择 1 个免费获得
获得后进入 RunBoardPage
```

### 主要事件

| 事件 | 结果 |
|---|---|
| 选择初始秘宝少女 | 加入背包或自动放入回路 |
| 点击确认 | BRANCH_SELECT |
| 长按卡牌 | CardDetailOverlay |

### 设计建议

```text
初始秘宝少女选择后，优先加入背包。
进入 RunBoardPage 后通过 FormationEdit 引导玩家摆入回路。
```

### 页面布局

| 角色等级 / 进度 | 底部角色框旁 |

## 17. 状态切换伪代码

```gdscript
func change_state(next_state: RunState) -> void:
    exit_state(current_state)
    current_state = next_state
    enter_state(current_state)

func enter_state(state: RunState) -> void:
    match state:
        RunState.MAIN_MENU:
            ui.show_page(PageType.MAIN_MENU_PAGE)

        RunState.START_NEW_RUN:
            create_new_run_data()
            change_state(RunState.CHARACTER_SELECT)

        RunState.CHARACTER_SELECT:
            ui.show_page(PageType.CHARACTER_SELECT_PAGE)

        RunState.RUN_INIT:
            init_run_values()
            change_state(RunState.START_CAMP)

        RunState.START_CAMP:
            ui.show_page(PageType.START_CAMP_PAGE)

        RunState.STARTER_TREASURE_SELECT:
            ui.show_page(PageType.START_CAMP_PAGE)

        RunState.BRANCH_SELECT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.BRANCH_SELECT)
            branch_manager.generate_options()

        RunState.BRANCH_RESOLVE:
            resolve_selected_branch()

        RunState.SHOP_NODE:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.SHOP)
            shop_manager.prepare_stock()

        RunState.SUPPLY_NODE:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.GENERIC_NODE_CHOICE)
            node_manager.prepare_node_choices("supply")

        RunState.GOLD_NODE:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.GENERIC_NODE_CHOICE)
            node_manager.prepare_node_choices("gold")

        RunState.SYNTHESIS_CHECK:
            var results = synthesis_manager.check_and_apply()
            if results.size() > 0:
                ui.show_overlay(OverlayType.SYNTHESIS_RESULT_POPUP, results)
            else:
                change_state(RunState.FORMATION_EDIT)

        RunState.FORMATION_EDIT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.FORMATION_EDIT)

        RunState.COMBAT_BRANCH_SELECT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.COMBAT_BRANCH_SELECT)
            battle_manager.generate_combat_options()

        RunState.COMBAT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.COMBAT)
            battle_manager.start_normal_battle()

        RunState.BOSS_INTRO:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.BOSS_INTRO)

        RunState.BOSS_COMBAT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.COMBAT)
            battle_manager.start_boss_battle()

        RunState.COMBAT_RESULT:
            ui.show_page(PageType.RUN_BOARD_PAGE)
            ui.set_run_board_mode(RunBoardMode.COMBAT_RESULT)
            resolve_combat_result()

        RunState.RUN_VICTORY:
            ui.show_page(PageType.RUN_VICTORY_PAGE)

        RunState.RUN_DEFEAT:
            ui.show_page(PageType.RUN_DEFEAT_PAGE)
```

## 18. CombatResult 处理逻辑

```gdscript
func resolve_combat_result() -> void:
    if current_battle_type == "normal":
        if last_combat_result == "win":
            normal_win_count += 1
            reward_manager.grant_combat_rewards()

            if normal_win_count >= normal_win_target:
                next_state_after_result = RunState.BOSS_INTRO
            else:
                next_state_after_result = RunState.BRANCH_SELECT
        else:
            run_durability -= 1

            if run_durability <= 0:
                defeat_reason = "durability_zero"
                next_state_after_result = RunState.RUN_DEFEAT
            else:
                next_state_after_result = RunState.BRANCH_SELECT

    elif current_battle_type == "boss":
        if last_combat_result == "win":
            next_state_after_result = RunState.RUN_VICTORY
        else:
            defeat_reason = "boss_lose"
            next_state_after_result = RunState.RUN_DEFEAT
```


| 是局内节点但仍要看到回路 | RunBoardMode |
| 需要完整离开局内主界面 | Page |
| 是局外系统 | Page |

## 24. 开发验收标准

### 24.1 页面验收

| 验收项 | 标准 |
|---|---|
| 独立页面数量清晰 | MainMenu、CharacterSelect、StartCamp、RunBoard、Victory、Defeat |
| RunBoardMode 清晰 | 分支、商店、通用节点选择、构筑、战斗、结算都在 RunBoard 内 |
| 节点不误做成页面 | Supply、Gold 复用通用 3 选 1；Synthesis、Formation、CombatResult 不单独切页 |
| 后续扩展不受限 | PageType、RunBoardMode、OverlayType 都可注册扩展 |
| 竖屏适配成立 | 1080×2340 下主要信息完整可读 |

### 24.2 流程验收

| 验收项 | 标准 |
|---|---|
| 开局可跑通 | 主菜单 → 角色选择 → 初始营地 → RunBoard |
| 一轮可跑通 | 分支 → 节点 → 合成 → 构筑 → 战斗 → 结算 |
| 商店可用 | 买、刷、锁、卖、离开 |
| 补给可用 | 通过通用 3 选 1选择恢复耐久或获得资源 |
| 金币节点可用 | 通过通用 3 选 1选择金币 / 资源奖励并继续流程 |
| 合成可用 | 2 个同名同稀有度自动合成 |
| 回路可编辑 | 最大 2×5，支持锁槽和占格 |
| 战斗可结算 | 胜利加普通战胜利数，失败扣耐久 |
| Boss 可触发 | 10 胜后进入 Boss |
| 终局可达成 | Boss 胜利 / 失败，或耐久归零 |
