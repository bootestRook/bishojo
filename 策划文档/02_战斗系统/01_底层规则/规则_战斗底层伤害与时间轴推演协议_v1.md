## 0. 文档目的

本文档用于统一 V1 阶段自动战斗底层的**伤害结算、冷却推进、状态处理、事件时间轴、战斗日志和 Codex 开发拆分协议**。

V1 战斗的核心不是战斗中手操，而是战斗前构筑后的自动验证：

```text
战斗回路摆位
+
冷却自动启动
+
充能连锁
+
站位联动
+
伤害 / 暴击 / 护盾 / 治疗 / 吸血 / 持续伤害
+
敌人行动
+
时间轴日志复盘
```

本协议要求底层战斗逻辑先稳定，再由表现层消费战斗日志播放动画、飘字、充能线、状态图标和结算反馈。

## 1. 核心定稿结论

V1 战斗底层采用：

```text
事件驱动时间轴
+
整数毫秒时间
+
确定性随机种子
+
冷却进度模型
+
统一 DamagePacket
+
状态分层处理
+
完整 BattleLog
```

不要采用：

```text
每帧直接扣冷却
+
动画播放时直接改血量
+
技能里散写伤害公式
+
状态效果各自临时插队
```

原因：

```text
充能会改变其他卡牌当前冷却
加速 / 减速会改变冷却恢复速度
冰冻会让冷却归零但不能主动行动
暴击会引入随机性，需要可复盘
剧毒 / 燃烧 / DOT tick 会插入未来时间轴
同一毫秒可能同时发生多个事件
连锁必须防无限循环
战斗结果必须能解释为什么赢 / 为什么输
```

## 2. 战斗定位与操作边界

### 2.1 战斗定位

一场战斗是当前构筑的一次自动验证。

玩家主要观察：

```text
谁先启动
谁给谁充能
充能链是否接上
站位关系是否生效
暴击是否带来爆发
持续伤害是否改变击杀时间
护盾 / 治疗 / 吸血是否撑住主角生命
敌人攻击节奏是否压垮防线
```

### 2.2 战斗中玩家操作

V1 战斗中不做实时手操：

```text
不手动释放技能
不战斗中换位
不手动选择目标
不暂停后下指令
```

可选表现功能：

```text
战斗播放加速
暂停查看数据
调试版跳过战斗
调试版展开事件日志
```

注意：UI 播放加速与卡牌状态“加速”必须分开命名。

```gdscript
battle_playback_speed     # UI 播放倍速
cooldown_haste_status     # 卡牌冷却状态：加速
```

## 3. 战斗对象分层

V1 战斗中至少有三类对象：

| 对象 | 说明 | 是否可死亡 |
|---|---|---:|
| 玩家战斗核心 / 主角 | 承受敌人攻击、剧毒、燃烧；拥有生命、护盾、治疗、吸血恢复收益 | 是 |
| 卡牌角色 / 秘宝少女 | 上阵组件，拥有冷却、技能、暴击、吸血、加速、减速、冰冻等状态 | V1 默认否 |
| 敌人 / Boss | 被卡牌伤害击败，按间隔攻击或施加状态 | 是 |

### 3.1 主角战斗生命与局内耐久分离

必须区分：

| 字段 | 层级 | 作用 |
|---|---|---|
| `player_core_hp` | 单场战斗 | 战斗内生命，归零则本场战斗失败 |
| `run_durability` | 一次 Run | 普通战失败后扣 1 点，归零整局失败 |

普通战失败流程：

```text
player_core_hp <= 0
↓
本场普通战失败
↓
run_durability -1
↓
run_durability > 0：进入下一轮
run_durability <= 0：整局失败
```

Boss 战失败流程：

```text
player_core_hp <= 0
↓
Boss 战失败
↓
整局失败
```

## 4. 时间单位与随机协议

### 4.1 时间单位

底层统一使用：

```text
显示单位：秒
计算单位：毫秒 int
```

示例：

| 显示 | 底层 |
|---:|---:|
| 0.5 秒 | 500 ms |
| 1 秒 | 1000 ms |
| 4 秒 | 4000 ms |

禁止用浮点秒做底层核心结算，避免同一时间点排序不稳定。

### 4.2 随机协议

暴击等随机事件必须满足：

```text
同一 battle_seed
+
同一输入阵容
+
同一敌人配置
=
同一战斗结果与日志
```

每次随机必须记录：

```gdscript
battle_seed
rng_roll_index
roll_type
roll_value_bp
threshold_bp
result
```

## 6. 战斗生命周期

```text
FormationManager 输出上阵快照
↓
BattleManager 创建 BattleContext
↓
初始化玩家核心生命 / 护盾 / 状态
↓
初始化卡牌冷却与状态
↓
初始化敌人生命与行动时间
↓
写入初始事件队列
↓
循环弹出事件并结算
↓
每次结算后检查胜负 / 超时 / 连锁上限
↓
战斗结束，输出 BattleResult + timeline_log
↓
RunManager 处理 CombatResult
```

战斗开始后：

```text
站位锁定
卡牌不可换位
玩家不可手动释放技能
目标选择由 target_rule 决定
所有结果通过日志复盘
```

## 7.3 同一时间点优先级

| priority | 事件 | 说明 |
|---:|---|---|
| 10 | 卡牌自然冷却检查 | 自然冷却归零 |
| 20 | 充能导致的卡牌触发 | 充能归零后立即启动 |
| 22 | 冰冻解除后补触发 | 冰冻结束且冷却已归零 |
| 25 | 卡牌技能效果 | 伤害 / 护盾 / 治疗 / 状态 / 充能 |
| 27 | 玩家来源对敌 DOT tick | 可选通用持续伤害 |
| 30 | 敌人死亡检查 | 敌人 HP 归零后结束或移除 |
| 40 | 敌人行动 | 攻击或施加状态 |
| 50 | 主角剧毒 tick | 忽视护盾 |
| 55 | 主角燃烧 tick | 护盾减伤，随后层数 -1 |
| 60 | 主角死亡检查 | player_core_hp <= 0 |
| 90 | 战斗超时 | 技术兜底 |

设计口径：

```text
同一毫秒内，卡牌行动优先于敌人行动。
同一毫秒内，治疗 / 护盾等卡牌效果优先于主角剧毒 / 燃烧 tick。
这样玩家能理解“我刚好在这一刻补上了防御”。
```

## 8. 冷却进度协议

## 8.1 初始化

V1 默认：

```gdscript
unit.remaining_cooldown_ms = unit.base_cooldown_ms * config.initial_cooldown_ratio_bp / 10000
unit.last_cooldown_update_time_ms = 0
unit.cooldown_rate_bp = 10000
```

`initial_cooldown_ratio_bp` 默认 `10000`，即开场完整冷却。

---

## 8.2 冷却推进

冷却不是每帧真正扣除，而是在事件发生时结算到当前时间。

```gdscript
func update_cooldown_to_now(unit: BattleUnitState) -> void:
    var elapsed_ms = battle.time_ms - unit.last_cooldown_update_time_ms
    if elapsed_ms <= 0:
        return

    var recovered_ms = elapsed_ms * unit.cooldown_rate_bp / 10000
    unit.remaining_cooldown_ms = max(0, unit.remaining_cooldown_ms - recovered_ms)
    unit.last_cooldown_update_time_ms = battle.time_ms
```

每次发生以下事件前，都必须调用：

```text
自然冷却检查
技能启动
技能启动后重置冷却
加速开始 / 结束
减速开始 / 结束
冰冻开始 / 结束
充能
```

---

## 8.3 下一次冷却检查时间

```gdscript
func calc_next_ready_time(unit: BattleUnitState) -> int:
    if unit.remaining_cooldown_ms <= 0:
        return battle.time_ms

    if unit.cooldown_rate_bp <= 0:
        return battle.time_ms + 999999999

    var time_needed = ceil_div(unit.remaining_cooldown_ms * 10000, unit.cooldown_rate_bp)
    return battle.time_ms + time_needed
```

每次冷却速度或剩余冷却改变后，需要增加版本号并重新入队：

```gdscript
unit.cooldown_version += 1
enqueue_cooldown_check(unit, calc_next_ready_time(unit), unit.cooldown_version)
```

旧事件弹出时，如果版本号不匹配，直接忽略。

---

## 8.4 自然冷却归零

```gdscript
func on_cooldown_check(unit: BattleUnitState, version: int) -> void:
    if battle.is_finished:
        return

    if version != unit.cooldown_version:
        return

    update_cooldown_to_now(unit)

    if unit.remaining_cooldown_ms > 0:
        schedule_next_cooldown_check(unit)
        return

    if unit.freeze_stack > 0:
        unit.is_ready_blocked_by_freeze = true
        log_ready_blocked_by_freeze(unit)
        return

    enqueue_player_trigger(unit, battle.time_ms, priority = 10)
```

---

## 8.5 技能启动后重置冷却

建议先重置自身冷却，再结算效果。

原因：

```text
如果技能效果中包含“给自己充能”，先重置冷却可以避免当前释放态和下一轮冷却态混乱。
```

```gdscript
func reset_unit_cooldown(unit: BattleUnitState) -> void:
    update_cooldown_to_now(unit)

    unit.remaining_cooldown_ms = unit.base_cooldown_ms
    unit.last_cooldown_update_time_ms = battle.time_ms
    unit.cooldown_version += 1

    schedule_next_cooldown_check(unit)
```

---

## 8.6 防同一毫秒无限启动

```gdscript
func can_trigger_now(unit: BattleUnitState) -> bool:
    return battle.time_ms - unit.last_trigger_time_ms >= config.min_trigger_interval_ms
```

如果同一单位被充能到 0，但距离上次启动不足 `min_trigger_interval_ms`：

```text
不丢弃充能
将下一次可触发时间延后到 last_trigger_time_ms + min_trigger_interval_ms
```

## 9. 卡牌状态协议

卡牌状态作用对象：

```text
卡牌角色 / 秘宝少女
```

V1 卡牌状态：

| 状态 | 内部 key | 作用 |
|---|---|---|
| 加速 | `haste` | 冷却恢复速度提升 100% |
| 减速 | `slow` | 冷却恢复速度变为常态一半 |
| 冰冻 | `freeze` | 不可主动行动 |
| 吸血 | `lifesteal` | 造成实际生命伤害后恢复玩家生命 |
| 充能 | `charge` | 立即减少伙伴当前冷却；不是持续状态 |

---

## 9.1 加速

状态机制：

```text
加速状态下，卡牌冷却恢复速度提升 100%。
```

底层：

```text
正常：cooldown_rate_bp = 10000
加速：cooldown_rate_bp = 20000
```

V1 同类加速默认不叠倍率，只刷新持续时间。

```gdscript
func apply_haste(unit: BattleUnitState, duration_ms: int) -> void:
    update_cooldown_to_now(unit)

    unit.haste_stack = 1
    unit.haste_end_time_ms = max(unit.haste_end_time_ms, battle.time_ms + duration_ms)

    recalc_cooldown_rate(unit)
    schedule_next_cooldown_check(unit)
    enqueue_card_status_expire(unit, "haste", unit.haste_end_time_ms)
```

---

## 9.2 减速

状态机制：

```text
减速状态下，卡牌冷却恢复速度是常态下的一半。
```

底层：

```text
正常：cooldown_rate_bp = 10000
减速：cooldown_rate_bp = 5000
```

V1 同类减速默认不叠倍率，只刷新持续时间。

---

## 9.3 加速与减速同时存在

V1 推荐使用乘法合成：

```gdscript
func recalc_cooldown_rate(unit: BattleUnitState) -> void:
    var rate_bp = 10000

    if unit.haste_stack > 0:
        rate_bp = rate_bp * 20000 / 10000

    if unit.slow_stack > 0:
        rate_bp = rate_bp * 5000 / 10000

    unit.cooldown_rate_bp = rate_bp
```

结果：

| 状态 | 冷却恢复速度 |
|---|---:|
| 无状态 | 100% |
| 只有加速 | 200% |
| 只有减速 | 50% |
| 加速 + 减速 | 100% |

---

## 9.4 冰冻

状态机制：

```text
冰冻状态下，卡牌角色不可主动行动。
```

V1 定稿解释：

```text
冰冻不停止冷却恢复。
冰冻只阻止主动启动。
冷却可以在冰冻期间归零。
冰冻结束时，如果冷却已经归零，立即补触发。
```

原因：

```text
冰冻是行动封锁，不是时间停止。
玩家可以理解为“技能已准备好，但被冻住不能放”。
```

冰冻结束：

```gdscript
func on_freeze_removed(unit: BattleUnitState) -> void:
    update_cooldown_to_now(unit)

    unit.freeze_stack = 0
    unit.freeze_end_time_ms = 0

    if unit.remaining_cooldown_ms <= 0:
        enqueue_player_trigger(unit, battle.time_ms, priority = 22)
    else:
        schedule_next_cooldown_check(unit)
```

---

## 9.5 充能

状态机制：

```text
充能立即减少伙伴当前冷却时间。
```

充能不是蓝条，也不是持续状态。

```gdscript
func apply_charge(source: BattleUnitState, target: BattleUnitState, charge_ms: int) -> void:
    update_cooldown_to_now(target)

    var before = target.remaining_cooldown_ms
    target.remaining_cooldown_ms = max(0, target.remaining_cooldown_ms - charge_ms)
    target.last_cooldown_update_time_ms = battle.time_ms
    target.cooldown_version += 1

    log_charge(source, target, charge_ms, before, target.remaining_cooldown_ms)

    if target.remaining_cooldown_ms <= 0:
        if target.freeze_stack > 0:
            target.is_ready_blocked_by_freeze = true
            log_ready_blocked_by_freeze(target)
        else:
            enqueue_player_trigger(target, battle.time_ms, priority = 20)
    else:
        schedule_next_cooldown_check(target)
```

冰冻 + 充能规则：

```text
被冰冻的卡牌可以被充能到 0。
但不会立刻行动。
等冰冻结束后立即补触发。
```

## 9.6 吸血

状态机制原文口径：

```text
吸血：回复 100% 造成伤害的生命，被护盾抵挡的值不计算。
```

本项目定稿解释：

```text
吸血状态 / 吸血属性挂在卡牌角色身上。
吸血收益恢复玩家战斗生命值 player_core_hp。
不是恢复卡牌角色生命。
```

详见第 14 节。

## 10. 主角状态协议

主角状态作用对象：

```text
玩家战斗核心 / 主角
```

V1 主角状态：

| 状态 | 内部 key | 作用 |
|---|---|---|
| 护盾 | `shield` | 1 层抵挡 1 点伤害，并减少 50% 燃烧伤害 |
| 治疗 | `heal` | 恢复生命，并清除治疗量 5% 的中毒和燃烧 |
| 剧毒 | `poison` | 忽视护盾，每秒造成 1 次伤害 |
| 燃烧 | `burn` | 每 0.5 秒造成 1 次伤害，并减少 1 层燃烧 |

---

## 10.1 护盾

规则：

```text
1 层护盾抵挡 1 点伤害。
护盾存在时，燃烧伤害先减少 50%。
```

普通伤害：

```gdscript
func apply_damage_to_player(amount: int, damage_type: String) -> DamageResult:
    var result = DamageResult.new()
    result.target_hp_before = battle.player_core_hp
    result.target_shield_before = battle.player_shield_stack

    var absorbed = min(battle.player_shield_stack, amount)
    battle.player_shield_stack -= absorbed

    var hp_damage = amount - absorbed
    battle.player_core_hp = max(0, battle.player_core_hp - hp_damage)

    result.final_damage = amount
    result.shield_damage = absorbed
    result.actual_hp_damage = hp_damage
    result.target_hp_after = battle.player_core_hp
    result.target_shield_after = battle.player_shield_stack

    return result
```

护盾上限：

```text
player_shield_stack <= player_core_hp_max × shield_cap_ratio_bp / 10000
```

V1 默认 `shield_cap_ratio_bp = 10000`，即护盾上限等于最大生命。

---

## 10.2 剧毒

规则：

```text
剧毒忽视护盾。
剧毒每 1 秒造成 1 次伤害。
默认每层剧毒每秒造成 1 点伤害。
```

剧毒需要持续时间或回合外清除来源。V1 建议配置 `poison_duration_ms`，否则剧毒会永久存在。

```gdscript
func on_poison_tick() -> void:
    if battle.player_poison_stack <= 0:
        return

    if battle.time_ms > battle.player_poison_end_time_ms:
        var before = battle.player_poison_stack
        battle.player_poison_stack = 0
        log_poison_expired(before)
        return

    var damage = battle.player_poison_stack * config.poison_damage_per_stack
    var hp_before = battle.player_core_hp

    battle.player_core_hp = max(0, battle.player_core_hp - damage)

    log_poison_tick(
        stack = battle.player_poison_stack,
        damage = damage,
        shield_ignored = true,
        hp_before = hp_before,
        hp_after = battle.player_core_hp
    )

    if battle.player_core_hp <= 0:
        finish_battle("lose")
        return

    enqueue_poison_tick(battle.time_ms + config.poison_tick_interval_ms)
```

## 10.3 燃烧

规则：

```text
燃烧每 0.5 秒造成 1 次伤害。
燃烧 tick 后减少 1 层燃烧。
护盾存在时，燃烧伤害先减少 50%。
```

建议默认：

```text
每层燃烧 = 1 点基础伤害
燃烧不需要 duration_ms，因为它会自然按层数衰减
```

```gdscript
func on_burn_tick() -> void:
    if battle.player_burn_stack <= 0:
        return

    var stack_before = battle.player_burn_stack
    var raw_damage = battle.player_burn_stack * config.burn_damage_per_stack
    var damage = raw_damage

    if battle.player_shield_stack > 0:
        damage = max(1, damage * 50 / 100)

    var shield_before = battle.player_shield_stack
    var hp_before = battle.player_core_hp

    var absorbed = min(battle.player_shield_stack, damage)
    battle.player_shield_stack -= absorbed

    var hp_damage = damage - absorbed
    battle.player_core_hp = max(0, battle.player_core_hp - hp_damage)

    battle.player_burn_stack = max(0, battle.player_burn_stack - 1)

    log_burn_tick(
        stack_before,
        battle.player_burn_stack,
        raw_damage,
        damage,
        absorbed,
        hp_before,
        battle.player_core_hp,
        shield_before,
        battle.player_shield_stack
    )

    if battle.player_core_hp <= 0:
        finish_battle("lose")
        return

    if battle.player_burn_stack > 0:
        enqueue_burn_tick(battle.time_ms + config.burn_tick_interval_ms)
```

关于 `max(1)`：

```text
V1 默认燃烧在有护盾时仍至少造成 1 点可被护盾吸收的伤害。
如果测试后希望低层燃烧可被完全压制，可改为 floor(damage * 50 / 100)。
```

## 10.4 治疗

规则：

```text
治疗恢复主角生命。
治疗清除治疗量 5% 的中毒和燃烧。
```

底层需要拆分两个函数：

| 函数 | 作用 | 是否清状态 |
|---|---|---:|
| `restore_player_hp` | 普通回血；吸血使用 | 否 |
| `apply_heal_to_player` | 治疗效果 | 是 |

```gdscript
func restore_player_hp(amount: int, source_type: String) -> int:
    if amount <= 0:
        return 0

    var hp_before = battle.player_core_hp
    battle.player_core_hp = min(battle.player_core_hp + amount, battle.player_core_hp_max)
    var actual_restored = battle.player_core_hp - hp_before

    log_player_restore_hp(source_type, amount, actual_restored, hp_before, battle.player_core_hp)
    return actual_restored
```

```gdscript
func apply_heal_to_player(heal_amount: int) -> void:
    var actual_restored = restore_player_hp(heal_amount, "heal")

    var cleanse_amount = heal_amount * config.heal_cleanse_bp / 10000

    var poison_before = battle.player_poison_stack
    var burn_before = battle.player_burn_stack

    battle.player_poison_stack = max(0, battle.player_poison_stack - cleanse_amount)
    battle.player_burn_stack = max(0, battle.player_burn_stack - cleanse_amount)

    log_heal_cleanse(
        heal_amount,
        actual_restored,
        cleanse_amount,
        poison_before,
        battle.player_poison_stack,
        burn_before,
        battle.player_burn_stack
    )
```

清除量按 `heal_amount` 计算，不按 `actual_restored` 计算。

理由：

```text
满血时使用治疗，也应该有清除中毒 / 燃烧的价值。
```

## 11. 通用持续伤害协议

《状态机制》已锁定主角侧剧毒与燃烧。除此之外，若卡牌需要对敌人施加持续伤害，使用通用 DOT 协议。

V1 分两层：

| 层级 | 状态 | 说明 |
|---|---|---|
| 必做主角 DOT | 剧毒 / 燃烧 | 作用于主角，规则固定 |
| 可配置对敌 DOT | 灼烧 / 中毒 / 流血 / 诅咒等 | 作用于敌人，走 `GENERIC_DOT_TICK` |

## 11.2 通用 DOT 默认边界

```text
DOT tick 默认不能暴击。
DOT tick 默认不能吸血。
DOT tick 默认不触发“造成伤害时充能”。
DOT tick 默认不触发“暴击时额外启动”。
```

V1 要求：



示例：

| 持续时间 | tick 间隔 | tick 时间 |
|---:|---:|---|
| 4000ms | 1000ms | 1s / 2s / 3s / 4s |
| 6000ms | 2000ms | 2s / 4s / 6s |
| 5000ms | 1000ms | 1s / 2s / 3s / 4s / 5s |

## 11.4 DOT 叠层规则

V1 只做两种：

| stack_rule | 含义 | 示例 |
|---|---|---|
| `refresh` | 不加层，只刷新持续时间 | 灼烧 |
| `stack_intensity` | 层数 +1，不超过上限，并刷新持续时间 | 流血 |

```text
DOT 净化
```

## 12. 伤害结算协议

## 12.1 伤害结算顺序

卡牌直接伤害：

```text
生成 DamagePacket
↓
读取 raw_damage
↓
计算伤害加成
↓
暴击判定
↓
计算暴击后伤害
↓
计算受伤加成 / 固定减伤
↓
扣目标护盾
↓
扣目标生命
↓
生成 DamageResult
↓
触发吸血 / 击杀检查 / 日志
```

主角剧毒 / 燃烧不走卡牌暴击逻辑，但仍应生成简化 DamagePacket 或等价日志。

---

## 12.2 直接伤害公式

```text
base_damage = raw_damage

damage_multiplier_bp =
    10000
    + source.damage_bonus_bp
    + packet.damage_bonus_bp
    + target.damage_taken_bonus_bp

pre_crit_damage = floor(base_damage × damage_multiplier_bp / 10000)
```

暴击后：

```text
if is_crit:
    damage_after_crit = floor(pre_crit_damage × final_crit_damage_bp / 10000)
else:
    damage_after_crit = pre_crit_damage
```

最终：

```text
final_damage = max(0, damage_after_crit - target.damage_reduce_flat)
```

## 13. 暴击协议

## 13.1 暴击字段

| 字段 | 含义 | 示例 |
|---|---|---:|
| `crit_rate_bp` | 基础暴击率 | 500 = 5% |
| `crit_rate_bonus_bp` | 战斗中暴击率加成 | 1000 = +10% |
| `crit_damage_bp` | 暴击总倍率 | 15000 = 150% |
| `crit_damage_bonus_bp` | 战斗中暴击伤害加成 | 5000 = +50% |
| `crit_resist_bp` | 被攻击方暴击抵抗 | 500 = -5% 暴击率 |

`crit_damage_bp` 是总倍率，不是额外倍率。

```text
15000 = 暴击后造成 150% 伤害
20000 = 暴击后造成 200% 伤害
```

---

## 13.2 暴击率公式

```text
final_crit_rate_bp = clamp(
    source.crit_rate_bp
    + source.crit_rate_bonus_bp
    + packet.crit_rate_bp
    - target.crit_resist_bp,
    0,
    config.crit_rate_cap_bp
)
```

## 13.3 暴击伤害公式

```text
final_crit_damage_bp =
    source.crit_damage_bp
    + source.crit_damage_bonus_bp
    + packet.crit_damage_bp_bonus
```

如果实现中没有 `packet.crit_damage_bp_bonus`，可先只使用：

```text
source.crit_damage_bp + source.crit_damage_bonus_bp
```

## 13.4 暴击判定

```gdscript
func resolve_critical(packet: DamagePacket, source: BattleUnitState, target) -> CriticalResult:
    var result = CriticalResult.new()

    if not packet.can_crit:
        result.is_crit = false
        return result

    var final_rate = clamp(
        source.stats.crit_rate_bp + source.stats.crit_rate_bonus_bp + packet.crit_rate_bp - target.stats.crit_resist_bp,
        0,
        config.crit_rate_cap_bp
    )

    var roll = battle_rng.roll_bp()

    result.crit_rate_bp = final_rate
    result.crit_roll_bp = roll
    result.is_crit = roll < final_rate
    result.crit_damage_bp = source.stats.crit_damage_bp + source.stats.crit_damage_bonus_bp
    result.rng_roll_index = battle.rng_roll_index

    log_crit_roll(result)
    return result
```

## 14. 吸血协议

## 14.1 最终口径

```text
吸血是卡牌角色状态 / 属性。
卡牌角色造成实际生命伤害后，按吸血比例恢复玩家战斗生命值 player_core_hp。
被护盾抵挡的伤害不计入吸血。
溢出伤害不计入吸血。
吸血回血不等同于治疗，默认不清除中毒和燃烧。
```

---

## 14.2 吸血计算

```text
actual_hp_damage = 目标生命实际减少值

lifesteal_heal = floor(actual_hp_damage × lifesteal_bp / 10000)

player_core_hp = min(player_core_hp + lifesteal_heal, player_core_hp_max)
```

必须使用：

```gdscript
damage_result.actual_hp_damage
```

禁止使用：

```gdscript
damage_result.final_damage
```

原因：

```text
final_damage 包含被护盾吸收的部分。
actual_hp_damage 才是目标生命真正减少的值。
```

---

## 14.3 吸血结算伪代码

```gdscript
func resolve_lifesteal(source: BattleUnitState, damage_result: DamageResult) -> void:
    if source.lifesteal_bp <= 0:
        return

    if damage_result.actual_hp_damage <= 0:
        return

    if not can_damage_trigger_lifesteal(damage_result):
        return

    var heal_amount = damage_result.actual_hp_damage * source.lifesteal_bp / 10000
    var actual_restored = restore_player_hp(heal_amount, "lifesteal")

    log_lifesteal(
        source.instance_id,
        damage_result.packet_id,
        damage_result.actual_hp_damage,
        source.lifesteal_bp,
        heal_amount,
        actual_restored
    )
```

---

## 14.4 哪些伤害默认触发吸血

| 伤害来源 | 默认触发吸血 | 说明 |
|---|---:|---|
| 卡牌直接伤害 | 是 | 主规则 |
| 卡牌暴击伤害 | 是 | 暴击提高实际生命伤害 |
| 卡牌 DOT tick | 否 | 防止持续伤害 + 吸血过强 |
| 反伤 | 否 | 后置 |
| 剧毒 | 否 | 作用于主角，不是卡牌对敌伤害 |
| 燃烧 | 否 | 作用于主角，不是卡牌对敌伤害 |
| 敌人攻击 | 否 | 敌人不触发玩家吸血 |

---

## 14.5 吸血与治疗区别

| 类型 | 是否回血 | 是否清中毒 / 燃烧 | 来源 |
|---|---:|---:|---|
| 治疗 | 是 | 是 | 主角治疗效果 |
| 吸血 | 是 | 否 | 卡牌造成实际生命伤害 |

文案建议：

```text
吸血：造成生命伤害时，按实际生命伤害恢复玩家生命。
治疗：恢复玩家生命，并清除治疗量 5% 的中毒和燃烧。
```

## 15.1 技能执行顺序

一个卡牌启动时：

```text
1. 检查是否可启动：未冰冻、未死亡、未被同毫秒限制阻塞
2. 记录 PLAYER_TRIGGER_SKILL 日志
3. 设置 last_trigger_time_ms
4. 先重置自身冷却
5. 按 effect_list 顺序逐个结算
6. 每个 effect 先解析目标，再结算数值
7. 每个 effect 后检查敌人死亡 / 主角死亡
8. 若战斗未结束，继续处理事件队列
```

## 16. 目标选择与站位协议

V1 战斗回路最大：

```text
2 行 × 5 列 = 10 个槽位
```

体型：

| 体型 | 占格 | 规则 |
|---|---:|---|
| 小型 | 1 格 | 1×1 |
| 中型 | 2 格 | 1×2，横向，不能旋转 |
| 大型 | 3 格 | 1×3，横向，不能旋转 |

战斗开始后：

```text
站位锁定
技能读取占用范围
中型 / 大型按整体实体处理
不能把多格单位拆成多个单位
```

---

## 16.1 支持的 target_rule

| target_rule | 含义 |
|---|---|
| `enemy_single` | 当前主要敌人，通常为第一个存活敌人 |
| `enemy_all` | 所有存活敌人 |
| `player_core` | 玩家战斗核心 |
| `self` | 自身卡牌 |
| `adjacent` | 自身占用范围左右紧邻卡牌 |
| `same_row` | 同排卡牌 |
| `same_col` | 与自身列范围有重叠的卡牌 |
| `front_back_overlap` | 另一行中与自身列范围有重叠的卡牌 |
| `longest_cooldown_ally` | 当前剩余冷却最长的友方卡牌 |
| `random_ally` | 随机友方卡牌，需记录 RNG |

---

## 16.2 多格单位关系读取

| 关系 | 判断方式 |
|---|---|
| 左右相邻 | 目标位于该卡牌占用范围左边或右边紧邻槽位 |
| 同排 | 与该卡牌处于同一行 |
| 同列 / 列重叠 | 与该卡牌占用列有重叠 |
| 前后对应 | 位于另一行，且列范围有重叠 |
| 角落 | 占用范围包含角落槽位 |
| 中列 | 占用范围包含第 3 列 |

示例：大型卡牌占据前排第 2～4 列：

```text
左侧相邻：前排第 1 列
右侧相邻：前排第 5 列
前后对应：后排第 2～4 列
中列关系：成立
```

## 17. 敌人行动协议

## 17.1 普通敌人

```gdscript
func on_enemy_action(enemy: EnemyState) -> void:
    if battle.is_finished:
        return

    if enemy.hp <= 0:
        return

    var packet = DamagePacket.new()
    packet.source_id = enemy.enemy_id
    packet.source_layer = "enemy"
    packet.target_layer = "player_core"
    packet.damage_kind = "enemy_attack"
    packet.damage_type = "physical"
    packet.raw_damage = enemy.attack_damage
    packet.can_crit = false

    apply_enemy_damage_to_player(packet)

    if battle.player_core_hp <= 0:
        finish_battle("lose")
        return

    enemy.next_action_time_ms = battle.time_ms + enemy.attack_interval_ms
    enqueue_enemy_action(enemy, enemy.next_action_time_ms)
```

## 19. 连锁保护协议

V1 必须防无限循环。

### 19.1 单位最小触发间隔

```text
min_trigger_interval_ms = 100
```

同一卡牌在极短时间内不能重复无限触发。

### 19.2 同一时间点连锁上限

```text
max_chain_events_per_same_time = 30
```

如果同一毫秒内连锁超过上限：

```text
剩余连锁延后到 time_ms + 1
```

不要直接丢弃，否则玩家会感到“充能失效”。

### 19.3 旧事件防重入

所有会被更新的未来事件都要带版本号：

```text
cooldown_version
status_version
event_version
```

旧事件弹出后版本不匹配，直接忽略并记录可选调试日志。

## 20. 时间轴推演样例 A：加速 + 冰冻

### 20.1 初始

```text
A：焰刃少女
基础冷却：4.0 秒
当前剩余冷却：4.0 秒

0.0s：战斗开始
t=1.0s：获得加速，持续 2.0 秒
t=2.4s：被冰冻，持续 1.0 秒
```

### 20.2 推演

| 时间 | 事件 | 冷却变化 |
|---:|---|---|
| 0.0 | 战斗开始 | A 剩余 4.0s |
| 1.0 | 获得加速 | 过去 1.0s，剩余 3.0s；之后 200% 恢复 |
| 2.4 | 被冰冻 | 加速期间经过 1.4s，按 200% 恢复 2.8s，剩余 0.2s |
| 2.5 | 冷却理论归零 | A 冰冻中，不启动 |
| 3.0 | 加速结束 | A 仍为冷却 0，但冰冻中 |
| 3.4 | 冰冻结束 | A 立即启动 |
| 3.4 | A 启动后 | 冷却重置为 4.0s |

结论：

```text
加速 / 减速影响冷却恢复速度。
冰冻影响能不能主动行动。
充能影响当前剩余冷却。
三者不能混成一个 next_ready_time。
```

## 21. 时间轴推演样例 B：暴击 + 吸血

### 21.1 初始

```text
玩家生命：30 / 50
A：血刃少女
A 吸血：100%
A 直接伤害：20
A 暴击率：20%
A 暴击伤害：200%
敌人生命：100
敌人护盾：15
```

### 21.2 事件

| 时间 | 事件 | 结果 |
|---:|---|---|
| 4.000 | A 启动 | 生成 direct DamagePacket，raw_damage = 20 |
| 4.000 | 暴击判定 | roll = 1380，crit_rate = 2000，暴击成立 |
| 4.000 | 伤害放大 | 20 × 200% = 40 |
| 4.000 | 护盾吸收 | 敌人护盾 15 → 0 |
| 4.000 | 扣生命 | 敌人 HP 100 → 75，actual_hp_damage = 25 |
| 4.000 | 吸血 | 回复 25 × 100% = 25 |
| 4.000 | 玩家生命 | 30 → 50，实际恢复 20 |

关键点：

```text
吸血按 actual_hp_damage = 25 计算，不按 final_damage = 40 计算。
被护盾抵挡的 15 不计算吸血。
溢出的 5 点治疗不保留。
吸血不清除中毒 / 燃烧。
```

## 22. 时间轴推演样例 C：主角护盾 + 剧毒 + 燃烧 + 治疗

### 22.1 初始

```text
player_core_hp = 50 / 50
player_shield_stack = 3
player_poison_stack = 4
player_burn_stack = 4
```

同一时间点存在：

```text
t=1.0s：治疗 20
t=1.0s：剧毒 tick
t=1.0s：燃烧 tick
```

### 22.2 按优先级结算

| 时间 | 事件 | 结果 |
|---:|---|---|
| 1.0 | 治疗 20 | HP 50 → 50，实际恢复 0 |
| 1.0 | 清状态 | cleanse = floor(20 × 5%) = 1；剧毒 4 → 3；燃烧 4 → 3 |
| 1.0 | 剧毒 tick | 剧毒忽视护盾，HP 50 → 47 |
| 1.0 | 燃烧 tick | raw = 3；有护盾，先减半为 1 |
| 1.0 | 护盾吸收燃烧 | 护盾 3 → 2，HP 不变 |
| 1.0 | 燃烧衰减 | 燃烧 3 → 2 |

结论：

```text
治疗即使满血也能清异常。
护盾不挡剧毒。
护盾能压制燃烧。
燃烧每 tick 后自然掉 1 层。
```

## 28. 最小验收标准

| 自动冷却 | 卡牌能按 base_cooldown 自动启动 |
| 冷却速度 | 加速使冷却恢复速度变 200%，减速变 50% |
| 加速 + 减速 | 默认互相抵消为 100% |
| 冰冻 | 卡牌冷却可归零，但不能主动启动 |
| 冰冻结束 | 若冷却已归零，立即补触发 |
| 充能 | 立即减少目标当前剩余冷却 |
| 充能连锁 | A 充能 B，B 归零启动后可继续影响 C |
| 冰冻 + 充能 | 目标可被充能到 0，但等冰冻结束再启动 |
| 暴击率 | 同一随机种子下暴击结果稳定 |
| 暴击伤害 | 暴击后按 crit_damage_bp 放大伤害 |
| 暴击日志 | 记录暴击率、随机数、是否暴击、暴击倍率 |
| 直接伤害 | 卡牌能扣敌人生命 |
| actual_hp_damage | 记录目标生命实际减少值，排除护盾吸收与溢出伤害 |
| 吸血 | 卡牌造成实际生命伤害后恢复 player_core_hp |
| 吸血不清异常 | 吸血回血不清中毒 / 燃烧 |
| 护盾 | 1 层护盾抵挡 1 点普通伤害 |
| 护盾 vs 燃烧 | 有护盾时，燃烧伤害先减少 50% |
| 剧毒 | 每 1 秒伤害，忽视护盾 |
| 燃烧 | 每 0.5 秒伤害，并减少 1 层 |
| 治疗 | 恢复主角生命 |
| 治疗清异常 | 清除治疗量 5% 的中毒和燃烧 |
| 通用 DOT | 可对敌人施加持续伤害并按时间轴 tick |
| DOT 默认边界 | 默认不暴击、不吸血、不触发连锁 |
| 站位目标 | 相邻 / 同排 / 同列 / 前后对应能正确读取多格单位占用范围 |
| 同时事件 | 同一毫秒内事件顺序稳定 |
| 胜利 | 敌人 HP 归零后立刻结束战斗 |
| 失败 | player_core_hp 归零后立刻结束战斗 |
| 兜底 | 超时或连锁过量不会卡死 |
| 日志 | 能解释每次冷却变化、充能、暴击、伤害、状态、回血和胜负 |

```text
战斗底层 V1 =

敌人行动

+
```

最关键技术原则：

```text
冷却系统必须使用 remaining_cooldown_ms + cooldown_rate_bp。
伤害系统必须统一 DamagePacket / DamageResult。
吸血必须按 actual_hp_damage 恢复 player_core_hp。
治疗和吸血必须分离，只有治疗清异常。
剧毒和燃烧是主角状态，按固定 tick 插入时间轴。
同一时间点必须固定优先级。
所有随机暴击必须可通过 seed 复盘。
所有连锁必须有上限保护。
```
