文件名：`总案_项目总案_v1.md`

## 0. 文档目的

本文档用于统一 V1 阶段的项目目标、核心玩法、整局流程、系统边界与开发验收标准。

V1 的目标不是完成商业化版本，而是验证以下核心机制是否成立：

```text
局内分支选择
+
局内商店构筑
+
秘宝少女收集与合成升格（2合1）
+
最大 2×5 战斗回路摆放（槽位按单局进程解锁）
+
秘宝少女占格尺寸：小型 / 中型 / 大型
+
冷却自动启动
+
充能连锁
+
站位联动
+
自动战斗验证
+
最终 Boss 通关目标
```

V1 应优先做出一个完整、可游玩、可调参的核心闭环原型。

---

## 1. 项目定位

### 1.1 一句话定位

玩家通过分支选择、商店购买、秘宝少女合成升格（2合1），以及最大 2×5 战斗回路中的槽位解锁、占格摆放和站位联动，构筑一套自动启动、互相充能、连锁释放的战斗系统，并在累计获得 10 场普通战胜利后挑战最终 Boss。

### 1.2 类型定位

```text
大巴扎like
+
局内商店构筑
+
自动战斗
+
回路摆位
+
冷却启动
+
充能连锁
+
轻 Roguelike Run 流程
```

### 1.3 V1 核心体验

V1 的核心体验不是战斗中的手动操作，而是战斗前的构筑决策：

```text
买什么
卖什么
锁什么
刷新还是存钱
追不追同名合成升格（2合1）
把不同占格的秘宝少女放在什么位置
当前解锁槽位是否够用
是否为中型 / 大型秘宝少女预留连续空格
让谁给谁充能
让哪条连锁先启动
当前构筑能不能通过下一场战斗
大体积秘宝少女是否值得占用更多槽位
```

## 2. V1 设计目标

V1 要验证的是一套系统是否好玩，而不是堆内容量。

### 2.1 必须验证的问题

| 验证点 | 要回答的问题 |
|---|---|
| 商店构筑 | 买卖、刷新、锁定是否有选择压力 |
| 分支选择 | 商店、补给、金币等分支是否能形成取舍 |
| 战斗回路 | 最大 2×5 回路、槽位解锁与多格占用是否能形成摆位压力 |
| 冷却启动 | 自动释放是否清晰、稳定、有节奏 |
| 充能连锁 | 减少冷却、带动其他单位启动是否有爽点 |
| 站位联动 | 相邻、同排、同列等规则在多格占用下是否有构筑价值 |
| 合成升格（2合1） | 玩家是否愿意追同名秘宝少女进行合成升格（2合1）强化 |
| Run 流程 | 多次选择、构筑、战斗后挑战 Boss 的结构是否成立 |

### 2.2 V1 不追求的目标

V1 不追求：

```text
完整剧情
完整美术
商业化系统
复杂角色养成
大量关卡
大量敌人
联网对战
长期存档
数值完全平衡
```

V1 只追求：

```text
核心闭环能跑通
核心机制能看懂
构筑选择有差异
战斗反馈能验证构筑
整局流程能完成胜利或失败
```

## 3. 核心术语定义

### 3.1 一场战斗

一场战斗是当前构筑的一次自动战斗验证。

流程为：

```text
开始战斗
↓
秘宝少女根据冷却自动启动
↓
触发伤害 / 护盾 / 充能 / 增益 / 站位联动
↓
敌人行动
↓
战斗胜利或失败
↓
进入结算
```

战斗中玩家暂不进行实时操作。

### 3.2 一轮

一轮是一次完整的局内循环，通常包括：

```text
分支选择
↓
分支节点处理
↓
合成升格（2合1）检查
↓
战斗回路调整
↓
战斗分支选择
↓
自动战斗
↓
结算
```

注意：V1 的“一轮”不等于固定一次商店，也不等于固定一次胜利。  
每轮开始时，玩家可能进入商店、补给、金币等不同分支。

### 3.3 一局 / 一次 Run

一局是从玩家点击开始新局，到整局胜利或整局失败为止的完整流程。

V1 的一局目标是：

```text
累计获得 10 场普通战胜利
↓
挑战最终 Boss
↓
战胜 Boss 则整局胜利
```

普通战失败不会推进普通战胜利数，只会扣除局内耐久。

## 4. V1 整局流程定义

### 4.1 完整流程

```text
开始新局
↓
选择角色
V1 暂时只有 1 个角色
预留角色能力字段，但先不实现角色能力
↓
获得初始金币
↓
进入初始营地
3 选 1 获得初始秘宝少女
↓
进入第 1 轮分支
商店 / 增加或恢复局内耐久 / 获得金币 等选项
↓
根据选择进入对应分支节点
↓
购买、刷新、锁定、出售、选择或领取补给
↓
合成升格（2合1）检查
↓
调整战斗回路（最大 2×5，按进程解锁槽位）
↓
进行占格与站位合法性检查
↓
选择战斗分支
↓
开始战斗
↓
战斗胜利或失败
↓
胜利：结算奖励，普通战胜利数 +1
失败：扣除 1 点局内耐久
↓
进入下一轮
↓
重复分支、商店、补给、战斗流程
↓
累计获得 10 场普通战胜利
↓
挑战最终 Boss
↓
战胜 Boss：整局胜利
↓
局内耐久归零或最终 Boss 失败：整局失败
```

### 4.2 当前定稿结论

```text
进度由“普通战胜利数”推进
容错由“局内耐久”控制
成长由“分支 + 商店 + 合成 + 回路调整”驱动
最终目标是击败 Boss
```

## 5. 角色选择

### 5.1 V1 定义

V1 保留角色选择流程，但暂时只有 1 个可选角色。

| 项目 | V1 定义 |
|---|---|
| 可选角色数量 | 1 个 |
| 是否实现角色能力 | 暂不实现 |
| 是否预留能力字段 | 是 |
| 是否影响战斗 | V1 暂不影响 |
| 是否影响商店 | V1 暂不影响 |

### 5.2 预留字段

建议角色数据先预留：

```text
character_id
character_name
character_description
character_ability_id
character_ability_enabled = false
```

V1 不开发多角色差异，只保留后续扩展入口。

## 6. 初始营地

### 6.1 初始营地作用

初始营地是正式分支循环前的起点。

功能包括：

```text
发放初始金币
提供 3 选 1 初始秘宝少女
进入第 1 轮分支
```

### 6.2 初始秘宝少女三选一

| 项目 | V1 定义 |
|---|---|
| 选项数量 | 3 个 |
| 玩家获得数量 | 1 个 |
| 获得方式 | 免费获得 |
| 来源池 | 初始秘宝少女池 |
| 是否允许刷新 | V1 暂不建议 |
| 是否允许重复 | V1 暂不建议 |

三选一的作用是让玩家开局就有一个初步构筑方向。

示例方向：

| 初始秘宝少女 | 倾向 |
|---|---|
| 焰刃少女 | 输出 |
| 雷铃少女 | 充能 |
| 冰镜少女 | 防御 |

## 7. 局内耐久与失败结构

### 7.1 局内耐久

V1 暂定玩家拥有 5 点局内耐久。

```text
run_durability = 5
run_durability_max = 5
```

### 7.2 普通战失败

```text
普通战失败
↓
局内耐久 -1
↓
如果局内耐久 > 0，进入下一轮分支
↓
如果局内耐久 <= 0，整局失败
```

### 7.3 普通战胜利

```text
普通战胜利
↓
获得奖励
↓
普通战胜利数 +1
↓
检查是否达到 10 胜
```

### 7.4 最终 Boss 失败

V1 定义为：

```text
最终 Boss 失败 = 整局失败
```

Boss 战失败不再扣耐久后重试。  
这样终局压力更清楚，流程也更简单。

## 8. 普通战胜利数与 Boss 解锁

### 8.1 普通战胜利数

V1 的整局进度由普通战胜利数推进。

```text
normal_win_count = 0
normal_win_target = 10
```

| 情况 | 处理 |
|---|---|
| 普通战胜利 | normal_win_count +1 |
| 普通战失败 | normal_win_count 不变 |
| normal_win_count < 10 | 继续进入下一轮分支 |
| normal_win_count >= 10 | 进入最终 Boss 挑战 |

### 8.2 Boss 解锁规则

```text
累计获得 10 场普通战胜利
↓
不再进入普通战分支
↓
进入最终 Boss 挑战
```

### 8.3 整局胜利条件

```text
战胜最终 Boss
```

### 8.4 整局失败条件

```text
局内耐久归零
或
最终 Boss 战失败
```

## 9. 分支节点系统

### 9.1 分支节点作用

分支节点用于让玩家在每次战斗前做资源方向选择。

玩家需要判断：

```text
现在是缺金币
还是缺秘宝少女组件
还是局内耐久太低
还是应该继续强化已有构筑
```

### 9.2 V1 分支类型

V1 先做三类分支：

| 分支类型 | 功能 | V1 优先级 |
|---|---|---|
| 商店分支 | 进入商店购买秘宝少女 | 必须做 |
| 补给分支 | 恢复或增加局内耐久 | 必须做 |
| 金币分支 | 直接获得金币 | 建议做 |

### 9.3 分支选择形式

V1 暂不需要复杂路线地图。  
可以先使用简单分支面板：

```text
每轮开始时出现 2～3 个分支选项
玩家选择其中 1 个
进入对应节点
节点结束后进入构筑整理
```

示例：

```text
[进入商店] [恢复 1 点局内耐久] [获得 4 金币]
```

## 10. 商店节点系统

### 10.1 商店功能

V1 商店节点包括：

```text
购买秘宝少女
刷新商店
锁定商店
出售秘宝少女
跳过商店
```

### 10.2 商店流程

```text
进入商店节点
↓
生成商店商品
↓
玩家购买 / 刷新 / 锁定 / 出售
↓
玩家确认离开
↓
合成升格（2合1）检查
↓
进入战斗回路调整
```

### 10.3 锁定商店规则

因为 V1 不是每轮都必定进入商店，所以锁定规则需要明确：

```text
如果玩家锁定商店
↓
下次进入商店节点时仍保留上次商品
↓
玩家可以解除锁定或继续锁定
```

### 10.4 商店基础参数

以下为暂定配置，后续可调：

| 参数 | V1 暂定 |
|---|---:|
| 每次商店商品数量 | 5 |
| 刷新消耗 | 待定 |
| 初始金币 | 待定 |
| 出售返还 | 待定 |
| 锁定费用 | 暂定免费 |
| 是否每轮必定出现商店 | 否，通过分支出现 |

## 11. 补给节点系统

### 11.1 补给节点作用

补给节点用于提供容错和资源调整。

### 11.2 V1 补给内容

V1 建议先做简单版本：

| 选项 | 效果 |
|---|---|
| 恢复局内耐久 | 当前局内耐久 +1，不超过上限 |
| 获得金币 | 获得固定金币 |

### 11.3 关于“增加生命”的命名

为避免和战斗内生命混淆，文档中统一使用：

```text
局内耐久
```

如果未来要区分，可以拆成：

| 类型 | 含义 |
|---|---|
| 恢复局内耐久 | 当前耐久 +1 |
| 增加局内耐久上限 | 最大耐久 +1，并可同时恢复 1 点 |

V1 优先做“恢复局内耐久”，暂不优先做上限成长。

## 12. 金币节点系统

### 12.1 金币节点作用

金币节点用于让玩家放弃商店机会，直接获得经济资源。

### 12.2 V1 定义

```text
选择金币分支
↓
直接获得固定金币
↓
进入合成检查与战斗回路调整
```

金币节点的价值是：

```text
缺钱时补经济
为下次商店做准备
降低路线选择单调性
```

## 13. 战斗分支系统

### 13.1 战斗分支位置

战斗分支发生在构筑调整之后：

```text
分支节点完成
↓
合成升格（2合1）检查
↓
调整战斗回路（最大 2×5，按进程解锁槽位）
↓
进行占格与站位合法性检查
↓
选择战斗分支
↓
开始战斗
```

### 13.2 战斗分支作用

战斗分支决定本场战斗面对的敌人和奖励结构。

V1 可以先做简单版：

| 战斗分支 | 特点 |
|---|---|
| 普通战 | 难度正常，奖励正常 |
| 高奖励战 | 难度略高，奖励更高 |
| 稳妥战 | 难度较低，奖励较少 |

最小实现可以只有 2 个普通战分支，差异体现在敌人属性和奖励上。

### 13.3 Boss 战

当普通战胜利数达到目标值后，不再进入普通战斗分支，转入最终 Boss。

```text
normal_win_count >= normal_win_target
↓
进入最终 Boss 挑战
```

## 14. 秘宝少女系统

### 14.1 定义

秘宝少女是玩家在局内获得、购买、上阵和合成的核心构筑单位。

每个秘宝少女既是角色，也是战斗回路中的功能组件。V1 中，秘宝少女还具有明确的**体型占格**，体型会影响其在战斗回路中的摆放成本和站位联动关系。

### 14.2 基础字段

每个秘宝少女至少需要以下字段：

```text
treasure_id
treasure_name
rarity
size_type
footprint_width
footprint_height
price
tags
base_cooldown
current_cooldown
effect_list
position_rule
upgrade_rule
description
```

其中 `rarity` 暂定为 4 档：

```text
绿
蓝
紫
黄
```

其中 `size_type` 暂定为 3 档：

```text
小型
中型
大型
```

### 14.3 体型与占格

V1 秘宝少女按体型分为 3 种：

| 体型 | 占格 | 固定形状 | 是否旋转 | 说明 |
|---|---:|---|---|---|
| 小型 | 1 格 | 1 行 × 1 列 | 不需要 | 最灵活，适合补位和早期构筑 |
| 中型 | 2 格 | 1 行 × 2 列 | V1 不旋转 | 需要同一行连续 2 个空槽 |
| 大型 | 3 格 | 1 行 × 3 列 | V1 不旋转 | 需要同一行连续 3 个空槽，构筑压力最大 |

V1 固定规则：

```text
中型秘宝少女固定占 1 行 × 2 列
大型秘宝少女固定占 1 行 × 3 列
中型和大型都横向摆放
V1 不做旋转
V1 不做跨行形状
```

### 14.4 占格摆放规则

秘宝少女上阵时必须满足：

```text
目标槽位已解锁
目标槽位为空
中型 / 大型需要同一行连续空槽
不能跨行
不能重叠
不能占用锁定槽位
```

一个秘宝少女占用多个槽位时，这些槽位都归属于同一个秘宝少女。拖拽、出售、下阵、合成、战斗读取时，都应按“一个秘宝少女实体”处理，而不是按多个槽位拆分成多个单位。

### 14.5 V1 内容量建议

| 内容 | 数量 |
|---|---:|
| 秘宝少女基础种类 | 12 个左右 |
| 体型类型 | 小型 / 中型 / 大型 |
| 稀有度档位 | 绿 / 蓝 / 紫 / 黄 |
| 实际数据配置方式 | 基础数据 + 稀有度数值倍率 + 体型占格 |
| 初始秘宝少女池 | 3～6 个 |
| 核心流派雏形 | 3 条 |

V1 不建议为每个稀有度重新设计一套技能机制。更稳的做法是：

```text
同一个秘宝少女保持核心技能不变
稀有度提升后主要强化数值
体型主要影响摆放空间和构筑成本
```

例如：

```text
绿：基础伤害 / 基础护盾 / 基础充能
蓝：数值提高
紫：数值继续提高
黄：数值达到最高档
```

### 14.6 稀有度定义

V1 稀有度暂定为：

| 稀有度 | 定位 |
|---|---|
| 绿 | 基础版本，容易获得 |
| 蓝 | 一次升格后的强化版本 |
| 紫 | 中后期核心版本 |
| 黄 | 最高稀有度版本 |

稀有度主要影响：

```text
伤害数值
护盾数值
治疗数值
充能数值
增益数值
金币收益数值
商店出现权重
购买价格
```

V1 不优先让稀有度改变复杂机制，避免合成后技能说明失控。

### 14.7 V1 类型分布

| 类型 | 数量建议 | 作用 |
|---|---:|---|
| 输出型 | 4 | 主要造成伤害 |
| 充能型 | 3 | 减少其他单位冷却，制造连锁 |
| 防御型 | 2 | 提供护盾、治疗或核心保护 |
| 站位型 | 2 | 根据位置关系提供强化 |
| 经济型 | 1 | 提供额外金币或资源收益 |

### 14.8 体型分布建议

V1 可以先使用以下分布，后续根据测试调整：

| 体型 | 数量建议 | 设计作用 |
|---|---:|---|
| 小型 | 6～7 | 构筑基础组件，灵活填格，适合早期 |
| 中型 | 3～4 | 更强但占连续 2 格，要求玩家规划空间 |
| 大型 | 1～2 | 高价值核心组件，占连续 3 格，形成明确取舍 |

大型秘宝少女不宜过多，否则 V1 的摆位会从“联动构筑”变成“空间拥堵”。

## 15. 战斗回路系统

### 15.1 定义

战斗回路是玩家摆放秘宝少女的棋盘，也是站位联动、占格取舍和充能目标判断的基础。

V1 战斗回路采用最大规格：

```text
2 行 × 5 列 = 10 个槽位
```

实际可用槽位不必一开始全部开放，而是随单局进程逐步解锁。具体解锁节奏作为配置项保留，后续根据测试调整。

### 15.2 最大棋盘规格

最大布局：

```text
[ 前1 ] [ 前2 ] [ 前3 ] [ 前4 ] [ 前5 ]
[ 后1 ] [ 后2 ] [ 后3 ] [ 后4 ] [ 后5 ]
```

每个槽位至少需要记录：

```text
slot_id
row
column
is_unlocked
occupant_treasure_id
```

槽位状态分为：

| 状态 | 含义 |
|---|---|
| 锁定 | 当前单局进程尚未解锁，不能放置 |
| 空闲 | 已解锁，可以放置秘宝少女 |
| 占用 | 已被某个秘宝少女占用 |

### 15.3 槽位解锁

V1 定义：

```text
战斗回路最大为 2 行 × 5 列
具体解锁数量与解锁节奏根据单局进程配置
槽位解锁不是固定写死规则
```

可调方向包括：

```text
根据普通战胜利数解锁
根据分支奖励解锁
根据营地 / 补给节点解锁
根据 Boss 前进度解锁
```

V1 开发时只需要先保证系统支持：

```text
读取当前已解锁槽位
显示锁定槽位
禁止向锁定槽位放置秘宝少女
在流程中增加解锁槽位的接口
```

具体几胜解锁、一次解锁几个槽位，后续放到配置表中调整。

### 15.4 秘宝少女占格规则

秘宝少女按体型占用不同槽位：

```text
小型：占 1 格，1 行 × 1 列
中型：占 2 格，固定 1 行 × 2 列
大型：占 3 格，固定 1 行 × 3 列
```

摆放规则：

```text
中型和大型必须横向占用同一行连续槽位
不能跨行
不能旋转
不能重叠
不能占用未解锁槽位
```

示例：

```text
小型可放：
[ A ]

中型可放：
[ A ][ A ]

大型可放：
[ A ][ A ][ A ]
```

### 15.5 多格单位的站位关系读取

由于中型和大型会占多个槽位，站位判断需要按“占用范围”处理。

V1 建议统一规则：

| 关系 | 判断方式 |
|---|---|
| 左右相邻 | 目标位于该秘宝少女占用范围左边或右边紧邻槽位 |
| 同排 | 与该秘宝少女处于同一行 |
| 同列 | 与该秘宝少女占用列有重叠 |
| 前后对应 | 位于另一行，且列范围与该秘宝少女有重叠 |
| 边角 | 占用范围包含边缘列或角落槽位 |
| 中列 | 占用范围包含第 3 列 |

示例：大型秘宝少女占据前排第 2～4 列时：

```text
左侧相邻：前排第 1 列
右侧相邻：前排第 5 列
前后对应：后排第 2～4 列
中列关系：成立，因为占据第 3 列
```

### 15.6 需要支持的站位关系

| 关系 | V1 是否支持 |
|---|---|
| 左右相邻 | 支持 |
| 前后对应 | 支持 |
| 同排 | 支持 |
| 同列 / 列重叠 | 支持 |
| 边缘 / 角落位置 | 支持 |
| 中列位置 | 支持 |

### 15.7 回路基础规则

```text
每个槽位最多被 1 个秘宝少女占用
一个秘宝少女可以根据体型占用 1～3 个槽位
空槽允许存在
锁定槽位不能放置
可拖拽调整站位
拖拽时需要显示占格预览
战斗开始后锁定站位
技能可以读取槽位关系
战斗中暂不允许换位
```

### 15.8 V1 不做

```text
旋转中型 / 大型秘宝少女
跨行形状
L 形、T 形等复杂占格
多层棋盘
战斗中解锁槽位
战斗中移动单位
```

V1 先把横向占格、槽位解锁、站位读取做稳定。

## 16. 冷却启动系统

### 16.1 定义

每个上阵秘宝少女都有自己的冷却时间。  
战斗开始后，秘宝少女根据冷却自动启动效果。

```text
冷却中
↓
冷却归零
↓
触发效果
↓
重置冷却
↓
继续冷却
```

### 16.2 V1 规则

| 规则 | V1 定义 |
|---|---|
| 冷却单位 | 秒 |
| 触发方式 | 自动触发 |
| 战斗中手动释放 | V1 不做 |
| 充能影响 | 减少当前剩余冷却 |
| 冷却归零 | 立即启动 |
| 触发后 | 重置冷却 |

### 16.3 暂不做的复杂规则

```text
手动释放技能
打断
沉默
眩晕
复杂攻速换算
多段冷却
冷却溢出继承
```

## 17. 充能连锁系统

### 17.1 定义

充能不是传统蓝条，而是减少其他秘宝少女当前剩余冷却。

```text
A 启动
↓
A 使 B 剩余冷却 -2 秒
↓
B 冷却归零
↓
B 立即启动
↓
B 再触发其他效果
```

### 17.2 V1 充能规则

| 规则 | V1 定义 |
|---|---|
| 充能本质 | 减少当前剩余冷却 |
| 充能对象 | 相邻 / 同排 / 同列 / 随机 / 冷却最长 |
| 充能数值 | 配置化 |
| 归零处理 | 目标立即启动 |
| 是否允许连锁 | 允许 |
| 是否需要防死循环 | 必须 |

### 17.3 防无限循环

V1 必须加入安全规则，例如：

```text
同一个秘宝少女在极短时间内不能重复无限触发
```

或：

```text
单次连锁队列最多处理固定次数
```

建议技术参数：

```text
max_chain_events_per_tick
min_trigger_interval
```

这不是玩法数值，而是防卡死机制。

## 18. 站位联动系统

### 18.1 定义

站位联动让“摆在哪里”成为核心决策。

因为 V1 存在小型、中型、大型三种占格，站位联动不是只读取单个槽位，而是读取秘宝少女的**占用范围**。

### 18.2 V1 站位规则

V1 先支持 4 类：

| 规则 | 示例 |
|---|---|
| 相邻 | 启动时影响自身占用范围左右紧邻的单位 |
| 同排 | 强化与自身处于同一排的单位 |
| 同列 / 列重叠 | 影响与自身占用列有重叠的单位 |
| 边缘 / 角落 / 中列 | 根据占用范围是否覆盖特殊槽位获得额外效果 |

### 18.3 多格单位的联动原则

中型和大型秘宝少女按占用范围参与站位判断。

```text
小型：以自身 1 个槽位判断
中型：以连续 2 个槽位判断
大型：以连续 3 个槽位判断
```

建议规则：

| 联动类型 | 多格单位处理 |
|---|---|
| 相邻 | 只看占用范围外侧紧邻槽位，不把自身占用的格子算作相邻 |
| 同排 | 只要在同一行即可成立 |
| 同列 | 只要列范围有重叠即可成立 |
| 前后对应 | 另一行中与自身列范围重叠的槽位成立 |
| 角落 | 占用范围包含角落槽位即可成立 |
| 中列 | 占用范围包含第 3 列即可成立 |

### 18.4 技能模板示例

| 模板 | 效果示例 |
|---|---|
| 相邻充能 | 启动时，使自身左右紧邻单位冷却减少 |
| 同排鼓舞 | 启动时，使同排单位下一次伤害提高 |
| 前后链接 | 启动时，使前后对应单位获得护盾或充能 |
| 边缘增幅 | 位于边缘列时，自身伤害提高 |
| 中列核心 | 占用中列时，充能效果提高 |
| 大型核心 | 大型单位启动时，影响前后对应多个槽位 |

### 18.5 V1 不做

```text
复杂连线动画
多层棋盘
地形
战斗中换位
旋转后联动规则
过度复杂的光环叠加规则
```

V1 的重点是先让玩家能看懂：

```text
这个秘宝少女占了哪些格子
它影响了哪些相邻 / 同排 / 同列单位
为什么这次充能或增益触发了
```

## 19. 合成升格系统（2合1）

### 19.1 定义

玩家获得多个同名秘宝少女后，可以通过 2合1 升格获得更高稀有度版本。

V1 的合成升格（2合1）不以复杂机制变化为主，而是主要强化数值，让玩家清楚感受到同名追取的收益。

### 19.2 V1 合成规则

V1 只做：

```text
2 个同名、同稀有度秘宝少女
↓
合成 1 个同名、下一稀有度秘宝少女
```

稀有度升格顺序：

```text
绿 + 绿 → 蓝
蓝 + 蓝 → 紫
紫 + 紫 → 黄
黄为 V1 最高稀有度，不能继续合成
```

| 规则 | V1 定义 |
|---|---|
| 合成条件 | 2 个同名、同稀有度秘宝少女 |
| 合成结果 | 1 个同名、下一稀有度秘宝少女 |
| 是否自动合成 | 建议自动合成 |
| 最高稀有度 | 黄 |
| 黄以上合成 | V1 不做 |
| 局外升格 | V1 不做 |

### 19.3 合成位置处理

合成时需要明确保留哪个单位的位置，避免玩家摆位被意外破坏。

建议规则：

```text
如果参与合成的单位中有上阵单位
↓
优先保留上阵单位的位置
↓
消耗另一个同名同稀有度单位
↓
原槽位中的单位升级为下一稀有度
```

如果两个单位都在背包中，则在背包中生成下一稀有度单位。

如果两个单位都已上阵，V1 建议：

```text
保留较早上阵或较靠前槽位的单位
另一个槽位变为空
```

该规则后续可以根据实际操作体验调整。

### 19.4 升格效果

V1 升格主要强化数值，不优先改变技能机制。

优先强化：

```text
伤害数值
护盾数值
治疗数值
充能数值
增益倍率
经济收益
```

谨慎强化：

```text
冷却时间
影响范围
额外触发次数
附加效果
```

原因是冷却、范围和额外触发次数会明显改变连锁结构，容易增加平衡成本。V1 可以保留配置字段，但默认以数值成长为主。

### 19.5 示例

```text
焰刃少女 · 绿
效果：造成 20 伤害

焰刃少女 · 蓝
效果：造成 30 伤害

焰刃少女 · 紫
效果：造成 45 伤害

焰刃少女 · 黄
效果：造成 65 伤害
```

```text
雷铃少女 · 绿
效果：相邻单位冷却 -1 秒

雷铃少女 · 蓝
效果：相邻单位冷却 -1.5 秒

雷铃少女 · 紫
效果：相邻单位冷却 -2 秒

雷铃少女 · 黄
效果：相邻单位冷却 -2.5 秒
```

以上数值仅为示例，不是最终平衡。

## 21. 奖励与结算

### 21.1 普通战胜利结算

```text
敌人被击败
↓
获得奖励
↓
普通战胜利数 +1
↓
检查是否达到 Boss 解锁条件
```

奖励类型可以包括：

```text
金币
秘宝少女
免费刷新
补给
其他后续扩展奖励
```

V1 优先做金币奖励。

### 21.2 普通战失败结算

```text
玩家失败
↓
局内耐久 -1
↓
不增加普通战胜利数
↓
如果局内耐久仍大于 0，进入下一轮
↓
如果局内耐久归零，整局失败
```

### 21.3 Boss 战结算

| 结果 | 处理 |
|---|---|
| Boss 胜利 | 整局胜利 |
| Boss 失败 | 整局失败 |

| 合成强化方向 | 主要强化数值 |

| 回路布局 | 最大 2 行 × 5 列 |
| 秘宝少女占格 | 小型 1 格 / 中型 1×2 / 大型 1×3 |

## 29. V1 验收标准

### 29.1 流程验收

V1 至少要能完整跑通：

```text
开始新局
↓
选择唯一角色
↓
获得初始金币
↓
初始营地 3 选 1
↓
进入分支选择
↓
选择商店 / 补给 / 金币
↓
购买或获得资源
↓
合成升格（2合1）检查
↓
调整战斗回路（最大 2×5，按进程解锁槽位）
↓
进行占格与站位合法性检查
↓
选择战斗分支
↓
开始自动战斗
↓
战斗胜利或失败
↓
胜利增加普通战胜利数
↓
失败扣除局内耐久
↓
累计 10 场普通战胜利
↓
挑战最终 Boss
↓
Boss 胜利或失败
↓
整局结算
```

### 29.2 玩法验收

| 验收项 | 标准 |
|---|---|
| 分支选择有意义 | 商店、补给、金币之间存在取舍 |
| 商店选择有意义 | 买、刷、锁、卖会影响后续构筑 |
| 摆位有意义 | 调整站位与占格能改变充能或战斗结果 |
| 占格有意义 | 小型、中型、大型单位在回路中形成不同摆放取舍 |
| 冷却可读 | 玩家能看出单位何时启动 |
| 充能可读 | 玩家能看出谁给谁减少了冷却 |
| 连锁成立 | 能出现 A 触发 B、B 触发 C 的效果 |
| 合成有追求 | 玩家愿意购买同名秘宝少女 |
| 普通战失败可接受 | 失败扣耐久但不立即结束整局 |
| Boss 有终局压力 | Boss 战决定整局胜负 |
| 整局能结束 | 可以明确胜利或失败 |

### 29.3 技术验收

| 验收项 | 标准 |
|---|---|
| 状态机稳定 | 所有流程跳转清楚，无卡死 |
| 数据可配置 | 秘宝少女、体型尺寸、稀有度倍率、槽位解锁、敌人、奖励能通过数据调整 |
| 槽位解锁正确 | 未解锁槽位不可放置，解锁后可参与摆放与站位判断 |
| 占格逻辑正确 | 小型占 1 格，中型横向占 2 格，大型横向占 3 格，不可越界、重叠、跨行或旋转 |
| 站位关系正确 | 多格单位能正确判断左右相邻、同排、同列、前后对应、边缘、中列等关系 |
| 连锁有保护 | 不会无限循环 |
| 战斗有兜底 | 不会无限持续 |
| 商店锁定正确 | 下次进入商店时能保留锁定内容 |
| 合成逻辑正确 | 2 个同名同稀有度秘宝少女能合成为 1 个同名下一稀有度秘宝少女 |
| 稀有度上限正确 | 黄品质不能继续合成 |
| Boss 解锁正确 | 10 场普通战胜利后进入 Boss |
| 耐久扣除正确 | 普通战失败扣 1 点，归零失败 |
| Boss 失败正确 | Boss 失败直接整局失败 |
